# Journey walk — 2026-11-02 (localhost, production build)

Three journeys walked end to end on `next build` + `next start` (branch `docs/journey-walk-2026-11-02` = `origin/main`
6c0e17f, #296 included), FR then AR. **Report only — nothing was fixed.**

Rank: **blocks** = the journey cannot be completed · **confusing** = it can, but a user is likely to get lost or misled
· **cosmetic** = visual only. Screenshots: `docs/journeys/walk-2026-11-02/` (cropped; nothing with personal data).

## Environment limits (not product bugs)

- **Images:** every Supabase image shows the grey placeholder and logs a 400 from `/_next/image` — this PC's DNS
  returns NAT64 addresses for Supabase, which Next 16's image optimizer refuses as private. Local only (known).
- **Turnstile:** `.env.local` has no Turnstile keys. A local `next start` then FAILS CLOSED on every protected submit
  (« La vérification de sécurité a échoué » on « Confirmer la demande ») — by design, see
  `src/lib/security/turnstile.ts`. The walk was rebuilt with Cloudflare's dummy keys from `.env.example`
  (`NEXT_PUBLIC_TURNSTILE_SITE_KEY` at build, `TURNSTILE_SECRET_KEY` at start; shell only, `.env.local` untouched).
- **Sign-in / sign-up forms:** Supabase Auth verifies their CAPTCHA token with the REAL secret, which a dummy token
  can never pass, so the forms cannot submit on localhost. The walk signs in through the cross-device reset link
  (`/nouveau-mot-de-passe?token_hash=…` → « Continuer », #294) instead. **Not walked: the real sign-in and sign-up
  submits, and the `/connexion?next=` return after a sign-in.** They need a check on the Vercel preview or production.
